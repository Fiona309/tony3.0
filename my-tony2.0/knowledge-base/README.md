# Tony 知识库 V3

这套目录把“事实、规则、产品、价格、案例和来源”分开管理。旧版
`scripts/knowledge-base` 暂时保留，便于现有接口兼容；新数据通过迁移脚本生成。

## 核心约束

- 社交媒体内容只能作为用户经验、案例线索或待验证假设，不能直接成为安全结论、通用配方。
- 安全规则必须有官方说明、专业机构、专业教材等高可信来源，并记录适用条件和例外。
- 产品官方参数和动态价格分开保存；价格必须记录来源与采集时间。
- 发色案例必须描述染前条件、染发历史、产品/配方、过程和结果，并计算完整度。
- 所有进入推荐链路的内容必须能通过 `source_id` 追溯。

## 目录

```text
knowledge-base/
├── colors/       网红名称映射与内部标准色
├── hair/         1-10 度底色、染漂历史影响
├── rules/        可行性、色彩与安全决策规则
├── products/     产品身份、色号、官方用法、动态价格
├── cases/        结构化染前—配方—染后案例
├── evidence/     未升级为规则的社区证据
├── ingestion/    新采集、尚未晋升为正式规则的官方事实
├── sources/      来源注册表与可信度
└── meta/         迁移报告
```

## 命令

```bash
npm run kb:migrate
npm run kb:validate
```

迁移可重复执行，不会删除旧库。下一步应先补官方来源和标准发色，再让应用检索 V3；在规则库仍为空时，不应把社区经验包装成专业结论。

## 标准发色 V1

`canonical-colors.json` 使用“深浅等级、主色调、辅色调、冷暖、饱和度”描述颜色；这是 Tony 内部检索语言，不是某个品牌的配方。色调词汇参考 Wella、L’Oréal Professionnel 和 Schwarzkopf Professional 的官方专业色卡。

`trend-aliases.json` 负责把“海王红、奶茶棕、雾霾蓝”等用户说法映射到一个或多个标准色。网红名称没有稳定色值，所以当前映射都要求结合目标图片确认；底色范围也标为待真实案例和 Tony 复核，不能据此直接承诺染发结果。

## 采集工作区

新抓取的资料先进入 `ingestion/`。即使来源是官方，也要确认产品线、地区版本、适用条件和字段完整性后，才能晋升到 `products/official-usage.json` 或 `rules/`。这样可以避免把某一个产品的比例误用到所有染膏。
